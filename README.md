## How I Like to Engineer

A few principles influence how I work:

- Understand the failure modes before celebrating the happy path.
- Make overload behaviour explicit.
- Prefer measurable evidence over assumptions.
- Keep operational complexity proportional to the problem.
- Automate repetitive work, but keep the automation understandable.
- Treat observability as part of system design—not an afterthought.
- Leave behind documentation, runbooks, and tools that help the next engineer.
- Build for users, even when the “users” are other engineers.

I value pragmatic engineering. The most sophisticated solution is not automatically the best one; the best solution is the one that remains reliable, explainable, and maintainable in production.
